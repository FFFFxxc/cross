# Панель Desiree: Vercel + Render + Neon

Панель размещается на Vercel, а Telegram/MAX-воркер остаётся отдельным Web
Service на Render. Оба сервиса используют одну базу Neon. Vercel не получает
Telegram-сессию, Telegram API hash или MAX-токен.

## 1. Сначала обновить Render

1. В Render откройте Web Service Desiree, который собирается из корневого
   `Dockerfile` этого репозитория.
2. Проверьте существующие переменные `DATABASE_URL`, `TG_SESSION_STRING`,
   `MAX_BOT_TOKEN`, `MAX_CHANNEL` и остальные Telegram-переменные. Не переносите
   их в Vercel.
3. Задеплойте новый commit. В логах должны появиться обычный запуск Desiree без
   второй Telegram-сессии.
4. Проверьте health URL `/` — ответ должен быть HTTP 200.
5. После запуска подождите до 30 секунд: воркер запишет
   `worker_heartbeat_at` в Neon.

Если прежняя строка Neon, Telegram-код или токен когда-либо публиковались в
чате/репозитории, сначала замените их у провайдера. В Git секретов быть не
должно.

## 2. Импортировать проект в Vercel

1. В Vercel выберите Git-репозиторий Desiree.
2. Укажите **Root Directory: `dashboard`**.
3. Framework Preset: **Next.js**.
4. Добавьте одну переменную Production/Preview:

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | pooled-строка Neon с `-pooler` и `sslmode=require` |

5. Нажмите Deploy. Build Command и Output Directory оставьте стандартными.

GitHub Pages здесь не подходит: панель использует серверные Next.js API и
прямое защищённое подключение к Neon. На Pages пришлось бы отдать строку
подключения к базе браузеру, что недопустимо.

Панель намеренно работает без пароля. Любой человек с публичной ссылкой может
видеть очередь и запускать действия публикации, поэтому ссылку нельзя размещать
публично.

## 3. Проверка

1. Откройте Vercel URL: панель должна сразу показать главную без формы входа.
2. На главной должно быть `Работает`. `Задержка` допустима кратко после сна
   Render; `Не в сети` означает heartbeat старше пяти минут.
3. Откройте очередь, проверьте картинки, сортировку по реакциям и просмотрам,
   фильтр видео.
4. Сохраните безвредный порог, например `Минимум реакций = 0`, и перечитайте
   страницу.
5. Запустите небольшой сбор — действие сначала будет `pending`, затем
   `completed`, когда Render проснётся.
6. Не нажимайте **Опубликовать** в production только ради проверки. Это реальная
   публикация в Telegram и MAX. Первый ручной пост отправляйте только после
   явного решения владельца.

## Откат

- Vercel: Promote предыдущий успешный Deployment.
- Render: откатить на предыдущий commit. Новые столбцы Neon аддитивные и не
  мешают старому коду.
- Если воркер ведёт себя неверно, временно поставить
  `TG_AUTOMATION_ENABLED=false`; очередь и история останутся в Neon.
