# Автоматизация Desiree Pez для Telegram и MAX

## Цель и границы

Расширить только репозиторий `typonik1/cross`. Авторизованный пользователь
этого сервиса — Desiree Pez (`@aidesigndd`). Репозиторий `animecrooss` и
reader-аккаунт «бьянка» не изменяются.

Desiree принимает команды в «Избранном» и во входящем личном чате от
владельцев из `TG_OWNER_IDS` (по умолчанию разрешён `8235497168`). Она хранит
список Telegram-источников, вступает в публичный источник при добавлении,
собирает старые и новые посты в очередь, публикует их по московскому
расписанию в `@webnmy`, а затем напрямую в новый MAX-канал
`https://max.ru/channel_animenaruto`.

## Поток публикации

1. `/add_source <ссылка>` нормализует ссылку, вступает в публичный канал и
   сохраняет канонический Telegram peer. Первый источник по умолчанию —
   `https://t.me/animeworldmem`.
2. `/parse`, `/parse_from`, `/parse_period` и `/parse_top` собирают публикации.
   Фоновое пополнение периодически сканирует все источники, пока очередь
   меньше установленного минимума. Новые публикации сразу добавляются в
   очередь, но не выходят вне расписания.
3. Альбом является одной единицей. Тип очереди определяется как `video`,
   `image` или `any`; активность считается по просмотрам, пересылкам и
   реакциям. Уникальность — `(source, album-or-message-key)`.
4. Планировщик использует `Europe/Moscow`. Начальные слоты: `08:00 any`,
   `10:00 any`, `12:00 any`, `14:00 video`, `18:00 any`, `21:00 any`.
   `/slot HH:MM TYPE [SOURCE]` меняет тип и необязательный источник слота.
5. Перед отправкой удаляются все видимые URL, скрытые ссылки, `@username`,
   кнопочные/рекламные строки и оставшиеся строки только из эмодзи. Обычный
   текст и его Telegram-форматирование сохраняются.
6. В `@webnmy` уходит очищенная копия без рекламного футера. Медиа для MAX
   скачивается самой пользовательской сессией Telethon во временный файл,
   поэтому ограничение Telegram Bot API в 20 МБ не применяется.
7. MAX-бот загружает файл в MAX API и публикует его с одной подписью:
   активный текст `НАШ ТГК` со ссылкой `https://t.me/webm4ik`. Подпись меняется
   командой `/signature ТЕКСТ | URL`. Числовой `chat_id` нового публичного
   канала определяется через `GET /chats/channel_animenaruto`.

## Команды

Сохраняются `/transfer`, `/transfer_from`, `/forward`, `/forward_from`,
`/status`, `/cancel` и `/help`. При включённой автоматизации `/transfer`
использует новую безопасную очередь и публикует выбранные посты немедленно;
`/parse` только наполняет очередь.

Добавляются `/add_source`, `/del_source`, `/sources`, `/parse`,
`/parse_from`, `/parse_period`, `/parse_top`, `/queue`, `/now`, `/times`,
`/slot`, `/unslot`, `/signature`, `/retry` и `/config`.

## Состояние и защита от дублей

Один слой хранения поддерживает SQLite локально и Neon/PostgreSQL при наличии
`DATABASE_URL`. Источники, настройки, очередь, выполненные слоты и
идентификаторы публикаций переживают перезапуск Render при Neon.

Элемент очереди проходит `pending -> processing -> published`. ID сообщения
Telegram сохраняется до отправки в MAX, поэтому после обычного перезапуска
MAX-этап можно продолжить без повторной Telegram-публикации. Неопределённый
результат POST в MAX переводится в `ambiguous` и автоматически не повторяется;
владелец видит ошибку и может применить `/retry ID` после проверки канала.

## Render и безопасное включение

Новый режим включается только при `TG_AUTOMATION_ENABLED=true`. До включения
сохраняется текущий перенос Desiree в `@webnmy`, поэтому первый автодеплой не
ломает существующую цепочку. Для прямой публикации задаются `MAX_BOT_TOKEN`,
`MAX_CHANNEL=channel_animenaruto` и `DATABASE_URL`.

Старый Telegram Bot API -> MAX relay отключается только во время контрольного
переключения, непосредственно перед включением прямой MAX-публикации. Это
предотвращает двойную отправку одного поста.

## Проверка

Тестами покрываются очистка текста/entities, ранжирование и тип медиа,
хранилище/дедупликация, команды владельца, расписание, возобновление между
Telegram и MAX, загрузка файлов потоково и разбор `message.body.mid`. Перед
публикацией выполняются полный `pytest`, компиляция Python и Docker build.
